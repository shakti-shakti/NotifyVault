═══════════════════════════════════════════════════════════════════
  PILLAR 1 — DEEP LINK EXTRACTOR
═══════════════════════════════════════════════════════════════════

Create DeepLinkExtractor.kt.

───────────────────────────────────────────────
1.1  PUBLIC API
───────────────────────────────────────────────

  object DeepLinkExtractor {
      fun extract(
          notification: Notification,
          packageName: String,
          context: Context
      ): ExtractedLink?
  }

  data class ExtractedLink(
      val uri: String,
      val source: LinkSource,
      val confidence: LinkConfidence
  )

  enum class LinkSource {
      EXTRA_LINK_URI,     // Notification.EXTRA_LINK_URI (Android 12+)
      EXTRA_SCAN,         // Found by scanning all extras
      CONTENT_INTENT,     // Found inside contentIntent's Intent data
      ACTION_INTENT,      // Found inside an action's Intent data
      LAUNCH_INTENT       // Found in the app's launch intent
  }

  enum class LinkConfidence { HIGH, MEDIUM, LOW }

───────────────────────────────────────────────
1.2  EXTRACTION ORDER (try in this exact order)
───────────────────────────────────────────────

  STEP 1 — Notification.EXTRA_LINK_URI
    - Android 12+ sets this explicitly.
    - If present and non-empty → HIGH confidence, return.

  STEP 2 — Scan the entire extras Bundle
    - Iterate every key in notification.extras.
    - For each value, check if it is:
        a) a String / CharSequence that parses as a URI
        b) a Uri object
        c) a Parcelable[] or ArrayList that contains Uris
    - For each candidate, apply the MATCH RULES below.
    - First match → MEDIUM confidence, return.

  STEP 3 — contentIntent's Intent data
    - Get notification.contentIntent.
    - Reflectively extract the wrapped Intent (via PendingIntent
      .getIntent() — if that fails, use the live map in Pillar 2).
    - If intent.data != null → MEDIUM confidence, return.

  STEP 4 — Action intents' data
    - For each Notification.Action, get its actionIntent.
    - Extract the wrapped Intent the same way.
    - If intent.data != null → MEDIUM confidence, return.

  STEP 5 — Launch intent fallback
    - context.packageManager.getLaunchIntentForPackage(packageName)
    - If it has a data URI → LOW confidence, return.

  STEP 6 — Nothing found
    - Return null.

───────────────────────────────────────────────
1.3  MATCH RULES (what counts as a deep link)
───────────────────────────────────────────────

  A string is a valid deep link if it matches ANY of:

  a) Starts with "http://" or "https://"
     → but filter out obvious noise:
        - image URLs ending in .png/.jpg/.webp/.gif
        - analytics/tracker URLs (google-analytics, doubleclick,
          facebook.com/tr, adjust.com, branch.io trackers)
        - favicon URLs
        - fonts / css / js files
     → keep only "content" URLs (message, article, post, item,
       product, thread, chat, order)

  b) Matches a known app deep-link scheme (whitelist):
        whatsapp://
        tg://
        instagram://
        fb://
        twitter://
        x://
        linkedin://
        slack://
        discord://
        spotify://
        youtube://
        gmail://
        googlegmail://
        upi://
        paytmmp://
        phonepe://
        gpay://
        amazon://
        flipkart://
        swiggy://
        zomato://
        and any scheme matching "<packageName>://"

  c) Contains a path fragment that suggests deep content:
        /message/     /chat/        /thread/
        /item/        /post/        /article/
        /product/     /order/       /tracking/
        /receipt/     /payment/     /invoice/

  d) Uses Android App Links format:
        "android-app://<package>/..."
        "intent://...#Intent;package=<package>;end"

───────────────────────────────────────────────
1.4  APPLY THE EXTRACTION
───────────────────────────────────────────────

  In NotificationListenerService.onNotificationPosted():
    - After building the entity, call DeepLinkExtractor.extract().
    - Store the result in NotificationEntity:
        deepLinkUri: String?
        deepLinkSource: String?   (LinkSource enum name)
        deepLinkConfidence: String? (HIGH / MEDIUM / LOW)
    - If a HIGH-confidence link already exists for the same
      (packageName, groupKey), don't overwrite it with a weaker one.


═══════════════════════════════════════════════════════════════════
  PILLAR 2 — LIVE PENDINGINTENT MAP
═══════════════════════════════════════════════════════════════════

PendingIntents are NOT serializable. They cannot be saved to Room.
They live only in memory. So we keep a thread-safe in-memory registry
while the NotificationListenerService is running.

───────────────────────────────────────────────
2.1  LIVE NOTIFICATION REGISTRY
───────────────────────────────────────────────

Create LiveNotificationRegistry.kt as a Hilt @Singleton.

  @Singleton
  class LiveNotificationRegistry @Inject constructor() {

      data class LiveEntry(
          val key: String,               // StatusBarNotification key
          val packageName: String,
          val notificationId: Int,
          val tag: String?,
          val postedAt: Long,
          val contentIntent: PendingIntent?,
          val deleteIntent: PendingIntent?,
          val actionIntents: List<ActionEntry>,
          val fullNotification: Notification
      )

      data class ActionEntry(
          val title: CharSequence,
          val actionIntent: PendingIntent?
      )

      // Thread-safe, LRU-capped
      private val map = ConcurrentHashMap<String, LiveEntry>()
      private val accessOrder = Collections.synchronizedList(
          LinkedList<String>()
      )

      private const val MAX_ENTRIES = 500

      fun put(entry: LiveEntry) { ... evictOldest if over cap ... }
      fun get(key: String): LiveEntry?
      fun remove(key: String)
      fun clear()
      fun contains(key: String): Boolean
      fun size(): Int
  }

  Requirements:
    - Thread-safe reads/writes (ConcurrentHashMap).
    - LRU eviction: when size > MAX_ENTRIES, drop the oldest
      by postedAt.
    - No memory leaks: entries hold references to Notification
      objects which may hold bitmaps. To prevent OOM, strip large
      bitmaps (EXTRA_LARGE_ICON, EXTRA_PICTURE) from the stored
      Notification before inserting into the map. Keep only the
      intents + light metadata.
    - Map is empty after service restart — that is correct and
      expected. ReplayEngine will fall back.

───────────────────────────────────────────────
2.2  WIRE INTO THE SERVICE
───────────────────────────────────────────────

  onNotificationPosted(sbn):
    - Build a LiveEntry from sbn.notification.
    - Strip heavy bitmaps first.
    - registry.put(entry).

  onNotificationRemoved(sbn):
    - registry.remove(sbn.key).

  onListenerDisconnected / onDestroy:
    - registry.clear().

  Expose the registry via Hilt so the UI layer can query it.

───────────────────────────────────────────────
2.3  GRACEFUL DEGRADATION
───────────────────────────────────────────────

  The UI must know in real time whether exact replay is possible.
  Add a StateFlow<Set<String>> to the registry that emits the set
  of live notification keys. The Detail screen collects this and
  toggles the status pill live.

  registry.liveKeys: StateFlow<Set<String>>


═══════════════════════════════════════════════════════════════════
  PILLAR 3 — REPLAY ENGINE (SMART FALLBACK CHAIN)
═══════════════════════════════════════════════════════════════════

Create ReplayEngine.kt. This is the brain that tries everything.

───────────────────────────────────────────────
3.1  RESULT TYPE
───────────────────────────────────────────────

  sealed class ReplayResult {
      object ExactReplay      : ReplayResult()  // fired live contentIntent
      object ActionReplay     : ReplayResult()  // fired a live actionIntent
      object DeepLinkReplay   : ReplayResult()  // used stored deep link
      object AppLaunch        : ReplayResult()  // opened app main activity
      object AppDetails       : ReplayResult()  // opened settings page
      object Failed           : ReplayResult()  // nothing worked
  }

───────────────────────────────────────────────
3.2  PUBLIC API
───────────────────────────────────────────────

  @Singleton
  class ReplayEngine @Inject constructor(
      private val registry: LiveNotificationRegistry,
      private val context: Context
  ) {
      fun replay(entity: NotificationEntity): ReplayResult
      fun replayAction(
          entity: NotificationEntity,
          actionTitle: String
      ): ReplayResult
  }

───────────────────────────────────────────────
3.3  REPLAY FLOW (try in this exact order)
───────────────────────────────────────────────

  STEP 1 — LIVE CONTENT INTENT
    - Build the same key used when capturing:
        key = "${entity.packageName}|${entity.notificationId}|${entity.tag ?: ""}"
    - Look up registry.get(key).
    - If entry exists and entry.contentIntent != null:
        try {
            entry.contentIntent.send()
            return ExactReplay
        } catch (PendingIntent.CanceledException) {
            registry.remove(key)
        } catch (Exception e) {
            log(e)
        }

  STEP 2 — LIVE ACTION INTENT (only if user tapped a specific action)
    - Same lookup. Find the ActionEntry matching actionTitle.
    - If found and its actionIntent != null → fire it.
    - Return ActionReplay on success.

  STEP 3 — STORED DEEP LINK
    - If entity.deepLinkUri != null:
        try {
            val intent = Intent(Intent.ACTION_VIEW, Uri.parse(uri))
                .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
                .setPackage(entity.packageName)
            context.startActivity(intent)
            return DeepLinkReplay
        } catch (ActivityNotFoundException) {
            // Some apps don't handle their own scheme via setPackage,
            // retry without setPackage:
            try {
                val intent2 = Intent(Intent.ACTION_VIEW, Uri.parse(uri))
                    .addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
                context.startActivity(intent2)
                return DeepLinkReplay
            } catch (ActivityNotFoundException) {
                log("deep link failed for ${entity.packageName}")
            }
        }

  STEP 4 — APP MAIN ACTIVITY
    - val launch = context.packageManager
          .getLaunchIntentForPackage(entity.packageName)
    - If launch != null:
        launch.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)
        context.startActivity(launch)
        return AppLaunch

  STEP 5 — APP DETAILS PAGE
    - Intent(Settings.ACTION_APPLICATION_DETAILS_SETTINGS,
             Uri.fromParts("package", entity.packageName, null))
    - Return AppDetails.

  STEP 6 — FAILED
    - Return Failed.

───────────────────────────────────────────────
3.4  SAFETY RULES
───────────────────────────────────────────────

  - Every startActivity and PendingIntent.send is wrapped in
    try/catch. Never crash.
  - All lookups are O(1) on the ConcurrentHashMap.
  - No disk I/O on the main thread. ReplayEngine methods should be
    called from a coroutine on Dispatchers.Main.immediate for the
    actual launch, but the lookup itself is instant.
  - Before firing a PendingIntent, optionally check
    `pendingIntent.isImmutable` — immutable intents from other apps
    will throw on send() in some cases. Handle it silently.

───────────────────────────────────────────────
3.5  PACKAGE VISIBILITY (Android 11+)
───────────────────────────────────────────────

  Add to AndroidManifest.xml:

    <queries>
        <intent>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
        </intent>
        <intent>
            <action android:name="android.intent.action.VIEW" />
            <data android:scheme="http" />
        </intent>
        <intent>
            <action android:name="android.intent.action.VIEW" />
            <data android:scheme="https" />
        </intent>
    </queries>

  Without this, getLaunchIntentForPackage returns null for most apps.
